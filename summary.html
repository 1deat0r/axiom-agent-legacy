Goal & assumptions

A gateway-local /cron command that schedules agent runs via the existing AgentCronJobStore and delivers each run’s output to the profile’s gateway channel. Success: /cron add <schedule> <prompt> persists a job; the scheduler boots a headless --profile turn at due; the reply goes to the creating channel (list/rm manage).

Assumptions: jobs are profile-scoped at getCronJobsPath(projectHome); cron runs reuse the CliCompletionRunner seam; only allowlisted senders reach commands; delivery targets the creating channel id.

Key decisions

  • Reuse, not rebuild: the baseline AgentCronJobStore + AgentCronScheduler + CliCompletionRunner are used as-is; channelId is additive and optional.
  • Skip undeliverable jobs: a run proceeds only for source==="cron" with a channelId, so a shared heartbeat store is never hijacked.
  • Process isolation: cron runs use a cron-<channel> session, distinct from the interactive gw-<channel> session (ADR-0014), so a due job never boots a second agent process on an interactive session.
  • Deterministic scheduling: GatewayCron.runDue(now?) is a thin seam over the scheduler for tests and operator sweeps.
  • Resilient error replies: command store ops are try/caught; rm resolves exact-id then unique-prefix; delivery failures surface “scheduled run failed”.
