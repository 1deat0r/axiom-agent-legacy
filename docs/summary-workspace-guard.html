Generated 2026-08-12 · Model: the coding agent that developed this repo · Loop v2

Goal & assumptions

Implement ADR-0014 rung-3 project isolation: when a run is anchored to a project, an edit whose resolved path leaves the project root is blocked with a plain-English reason surfaced to the model; the completion child runs with cwd = root and AXIOM_PROJECT_ROOT set; tests fail without the guard.

A1Only the structured edit tool carries a reliably resolvable path; bash/ipython are freeform and are the ADR OS-sandbox tier (follow-up), recorded not faked.

A2Guard is inert unless AXIOM_PROJECT_ROOT is set → no impact on ordinary runs.

A3Reads/context drift are rung-2 (per-project memory); rung-3 targets writes.

A4--project requires an existing dir; fails fast like the telegram-token rule.

Key decisions

  • Guard is default-inert: no root → no-op, minimal blast radius (A2).
  • Both root and target realpath-normalized (symlinked root / symlink-escape caught); new files resolve to nearest existing ancestor and rebase.
  • Block returns {block, reason} → becomes an error tool-result (agent-loop.prepareToolCall:827) naming the allowed root.
  • Lifecycle: one gateway process = one profile = (when anchored) one project; root read at child boot.
  • Honest boundary: bash/ipython confinement and a per-project escape allowlist are recorded ADR follow-ups, not shipped.
