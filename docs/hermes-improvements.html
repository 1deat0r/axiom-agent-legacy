Axiom can grow toward what Hermes already has

A read-only capability-parity review: which features of the Nous Research Hermes agent are worth porting onto Axiom's TypeScript prime-agent baseline — ranked by value, fit with Axiom's money thesis, and effort. Everything below is grounded in the actual sources of both repos, not in memory.

The one-line read: Hermes is a research-grade, platform-maximal agent — dozens of messaging transports, a delivered-automation spine, FTS5 cross-session recall, and skills that learn. Axiom is small, typed, cost-capped, and gateway-first. The highest-leverage ports are the three that extend what Axiom already built — automations that deliver to your gateway, cross-session recall, and more transports — rather than replicating Hermes' scale.

04 Priority board

The three tiers, each with why it fits Axiom's creed, the cheap first step, and the score bars (value · fit · effort).

TIER 1 · ADOPT

1 · Automation spine scheduled + event-triggered, delivered

VALUE 5 · FIT 5 · EFFORT 3

The single biggest gap. Axiom's heartbeat/cron store can become a real automation product: /cron jobs that boot a headless --profile turn and deliver the result to a gateway channel; a gateway webhook/REST route (HMAC) plus GitHub-event triggers; optional pre-prompt script injection with the [SILENT] pattern. This is the money thesis made visible — nightly cost reports, weekly digests, watchdog summaries delivered straight to Telegram.

Hermes: cron/scheduler.py · tools/cronjob_tools.py · gateway webhook · “routines” (scheduled / GitHub / API) · unlimited · per-job models
Axiom now: internal AgentCronJobStore (heartbeat/rlm sources) — no delivery, no external triggers
First step: a /cron command that reuses the existing job store but delivers each run's output to the profile's gateway channel.

2 · Cross-session recall search the past

VALUE 4 · FIT 5 · EFFORT 3

Memory today is a durable-fact store that cannot answer “what did we decide about X last month?”. Adding an FTS5 index over the SQLite session DB gives discovery / scroll / browse modes and LLM-summarized recall, and lets memory be surfaced from past sessions rather than only hand-recorded. This is Axiom’s “memory survives the window” thesis taken further.

Hermes: native FTS5 CJK tokenizer · tools/session_search_tool.py (discovery/scroll/browse, zero-LLM shapes) · hermes_state_search.py · memory plugin ecosystem
Axiom now: memory tool (facts, LRU); no search; /cost is an O(n) scan
First step: a /search slash command over an FTS5 index of the session DB, before any LLM summary layer.

5 · Delegate + script-as-tool RPC

VALUE 3 · FIT 4 · EFFORT 3

Axiom already has RLM subagents. The distinct Hermes trick is letting a plain script drive tools over RPC so a multi-step pipeline collapses into one compact, zero-context-cost turn — the parent never sees the intermediate calls. That’s a direct token saver and a good fit for the ledger’s “never guess spend” ethos.

Hermes: tools/delegate_tool.py (isolated context, batch/parallel) · async_delegation · delegation_output_schema
Axiom now: prime RLM subagents; no script→tool RPC collapse

05 Recommended sequence

Three horizons that build on each other, stay read-only-friendly, and keep the money thesis (cost visible, spend capped, demonstrable agents) as the yardstick.

H1 Deliver + recall + reach

Ship the three Tier-1 ports that extend what Axiom already built. Small, typed deltas on the existing seams — no new architecture.

  • Automation spine: /cron → delivered run results → gateway channel, plus a webhook/REST trigger
  • FTS5 /search over the session DB
  • A Discord transport behind the existing GatewayTransport

H2 Skills & guard deepen

Let Axiom remember how, not just what, and harden the fence it already started.

  • Auto-capture complex tasks as skills; skills hub + provenance + AST audit
  • Approval ladder: URL-safe fetch, sensitive-tool fence
  • Script-as-tool RPC to collapse pipelines and save tokens

H3 Parked / watch

Track but don't build yet. These change the runtime shape, not the capability surface.

  • Remote terminal backends + serverless idle (only when a remote modality is real)
  • Voice-note transcription + TTS on the gateway
  • Cross-platform continuity (relay/mirror) alongside the transport work
