Gateway live project switching + /projects menu

2026-08-12 · model: claude (axiom harness default) · repo: axiom-agent · branch: feat/gateway-project-switch

Goal & assumptions

Live per-channel project switching on the gateway: /projects use <name> persists an active project per chat; subsequent agent messages on that chat run anchored to that project (cwd + AXIOM_PROJECT_ROOT + existing bwrap confinement) with a project-scoped session; /projects renders a friendly menu. Success: a chat can list, switch, and run anchored, with clear errors, and an unset active project behaves exactly as today (back-compat). Assumptions: (1) active project is PER-CHANNEL, persisted under the profile home; (2) "menu" this PR = structured text menu (Telegram inline-keyboard/callback_query menus are a separate documented follow-up); (3) a per-channel active project overrides the boot --project anchor for that channel.

Key decisions

  • Per-channel store + generation: active-projects.json; removeProject bumps generation so a re-created project derives fresh session ids (deterministic FNV would otherwise resume the pre-rm conversation)
  • Composite session key: channel:project:generation drives BOTH the index key and the session id; switching resumes, never leaks the unanchored session
  • Effective-root threading: per-call projectRoot threads bwrap mount, cwd, AXIOM_PROJECT_ROOT, [sandbox-confined] prefix; fail-closed preserved
  • rm hardening: NAME_RE + containment guard fixes a pre-existing traversal (rm .. deleted the profile home); store cleared across channels; composite mappings dropped (removeWhere)
  • Self-healing resolve: invalid stored name (hand-edited file) or out-of-band delete -> store cleared + composite mapping dropped + unanchored; menu never lies
