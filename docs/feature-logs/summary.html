Goal & assumptions

A gateway-local /search <query> command that answers "what did we decide about X in a past session?" by full-text (FTS5) searching the agent's session archive — scoped to the anchored project by default, crossing projects only via an explicit guarded --all, with every hit labeled by its project so projects never mix silently. Success: ranked hits; anchored runs never leak another project; ./test.sh floor holds; biome + tsgo clean.

Assumptions: "session DB" = the repo's real archive (append-only JSONL under the profile's sessions dir); the vendored session-backends/sqlite-node is dist-only & unwired, so we index the actual corpus. FTS5 via node:sqlite stdlib (no new dep). A session belongs to a project iff its header cwd is under that project's root.

Key decisions

  • Build the index over the real JSONL archive (not the dist-only sqlite-node) — smallest correct surface.
  • In-memory FTS5 index per call (:memory:) with caps (2000 files / 64 KB per session / 4 KB per message). Persistence/incremental indexing is a documented follow-up, not v1.
  • Trigram tokenizer — substring / CJK-friendly recall; enforced 3-char minimum with a friendly message.
  • Project isolation: default scoped to projectRoot; --all is the only cross-project path and every hit is labeled by project. Unanchored runs treat the profile as one workspace.
  • resolveSessionsDir mirrors main.ts's profile→agent-dir rule (default vs named profile).
