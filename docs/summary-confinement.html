Axiom — OS-tier confinement for anchored runs

ADR-0019 · Feature Implementation Loop v2 · 2026-08-12 · model: coding agent (Axiom)

Goal & assumptions

Close the last ADR-0018 gap: freeform bash/ipython can no longer write to or read sensitive data outside the project. Anchored gateway runs spawn the whole completion child inside a bubblewrap sandbox — one kernel-enforced boundary covers bash, the ipython kernel, and every subprocess (inherited mount namespace). Assumptions: confinement == anchored (projectRoot set); fail-closed without bwrap; host stays readable (secret dirs shadowed); network inherited.

Key decisions

Whole-child wrap, not per-command string wrapping. String-guarding freeform bash is exactly the gap ADR-0018 flagged; wrapping the child at the gateway spawn gives one OS layer that confines bash + ipython together.

Deployment-safe mount model. A wholesale --tmpfs <home> would hide axiom's own CLI / node_modules under $HOME and break every anchored run. Kept --ro-bind / / (complete write confinement) + explicit --tmpfs shadows of ~/.ssh .aws .gnupg .config .local .cache .netrc.

Fail-closed. Absent bwrap returns a clear error — an anchored run never runs unconfined.

Observability. AXIOM_CONFINED=1 marker + [sandbox-confined] reply prefix.
