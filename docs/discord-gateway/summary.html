1Goal & assumptions

  • Both receive via REST long-poll per channel (Discord <code>getMessages?after=</code> snowflake; Slack <code>conversations.history</code> by message <code>ts</code>), not websocket — mirrors Telegram; websocket realtime is a follow-up.
  • channelId = platform channel id (drives the channel index); sender = author/user id (drives the shared config.json allowlist).
  • Slack reports API errors as HTTP 200 <code>ok:false</code> bodies (like Telegram); the fatal set is invalid_auth/not_authed/account_inactive/token_revoked.
  • Delivery ledger / Slack-or-Discord low-latency / fan-out: out of scope for these first steps.

3Key decisions

  • Selection: --transport discord|slack + tokens; unknown values error; missing token fails fast; default stays signal.
  • Receive: per-channel cursor long-poll; cursors persisted (discord-cursor.json, slack-cursor.json) for no-replay; Slack's inclusive oldest is filtered to strict-greater ts.
  • Identity: channel id -> channel index; author/user id -> allowlist gate.
  • Per-channel isolation: a channel 403/429/5xx (Discord) or channel_not_found/rate_limited (Slack) is logged (throttled) and skipped; only fatal token errors stop the loop.
  • Fatal: Discord 401; Slack ok:false invalid_auth etc.
  • Chunking: reuse the shared chunker at Discord 2000 / Slack 40,000 char caps.
