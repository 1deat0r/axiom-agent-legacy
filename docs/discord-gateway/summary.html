1Goal & assumptions

  • Discord + Slack receive via REST long-poll per channel (snowflake / message-ts cursor), not websocket; websocket realtime is a follow-up.

  • Fan-out is single-writer JSONL + send-only siblings (never connected); cross-transport reach is real when sibling tokens are present, inert-by-config otherwise. Websocket + relay/mirror/TTS remain follow-ups.

3Key decisions

  • Selection: --transport discord|slack + tokens; missing token fails fast; default stays signal.
  • Receive: per-channel cursor long-poll; cursors persisted for no-replay; Slack's inclusive oldest filtered to strict-greater ts.
  • Identity: channel id -> channel index; author/user id -> allowlist gate.
  • Per-channel isolation + fatal: channel 403/429/5xx ok logged+skipped; only fatal token errors stop the loop.
  • Chunking: shared chunker at Discord 2000 / Slack 40,000 caps.
  • Continuity: one deliverVia path records reply/denial/command/fan-out/cron; deliverToAll fans to every deliverTo channel (cross-transport when named); cron writes the SAME ledger; commands stay sync.
  • Cross-transport: deliverTo{transport,channel}; unknown names degrade to active, ledger labels the ACTUAL transport; CLI builds send-only siblings from present tokens (never connected).
