Telegram gateway · second transport

feature summary · 2026-08-12 (UTC) · Feature Implementation Loop v2 · deepseek-v4-flash

Goal & assumptions

Second transport on the axiom gateway surface, mirroring the Signal gateway (ADR-0016) module-for-module: the agent, riding a profile's SOUL.md, is reachable over Telegram (Bot API over HTTPS — no linked daemon). One chat = one session; same router, completion runner, channel index, commands, allowlist.

Success criterion: axiom gateway --transport telegram --profile <name> boots over Telegram, long-polls getUpdates with offset ack + persistence (no-replay on restart), routes to agent replies or gateway commands, chunks outbound at the 4096-char cap, and denies unknown/group chats by default — tests + npm run check+tsgo+build green; live bot pass token-gated and open.

  • Transport selection becomes real (--transport signal|telegram) — this fixes the inert --transport signal flag the Signal feature left un-plumbed.
  • TelegramClient boundary (sendMessage + long-poll getUpdates), real HttpTelegramClient over fetch exercised against a local server, fake injected in tests — nothing fabricated.
  • channelId = sender = String(chat.id); private chats allowlisted by the owner's id, group chats (negative id) denied by the existing allowlist unless listed.
  • Outbound chunking at the 4096-char sendMessage cap + send-failure surfacing; fatal (401/409) vs transient (retry) poll errors.

Key decisions

  • Real transport selection — --transport signal|telegram actually routes; default keeps Signal's exact prior behavior.
  • Offset persistence — <AXIOM_HOME>/gateway/telegram-offset.json; at-most-once batch ack (crash-between-return-and-deliver loses a batch, deliberately traded for no-replay).
  • Fatal vs transient — the client surfaces the real error_code (401 bad token / 409 conflicting poll stop the loop; network/5xx retry after backoff). Offset-write failure logs, never silent.
  • 4096 chunking — split at last whitespace ≤4096, hard-split fallback for a giant unbroken token; a failing chunk logs and stops the batch.
  • Group denial — negative chat.id never matches a positive-id allowlist, so groups are denied by the existing deny-before-model gate unless allowlisted.
